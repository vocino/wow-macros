## Secure vs insecure / taint basics

- Execution starts secure. Any read of addon-introduced (/script, addon) code or data taints the path. Taint is sticky (described as honey): it persists until reload/relog. Blizzard-signed FrameXML loads secure; all third-party addon code and saved variables load tainted.
- Terminology: secure = without taint. Protected function = callable only from secure execution. Protected frame = locked down in combat. Protected method = may not be called on a protected frame from taint in combat.
- Taint-safe post-hooking only: hooksecurefunc(table, name, fn) runs AFTER the original; Frame:HookScript runs after existing scripts. Neither spreads taint to the protected call.
- /script (and /run) executes TAINTED single-line Lua: "will not let you bypass Lua scripting limitations or UI restrictions." Patch 9.1.5 (2021-11-02): several APIs protected from direct /script calls.

## Works-in-combat classification (principle: slouken 2006 post)

Addons/macros CAN cast, but only with human interaction per action: no logic that intelligently picks spells/targets. A player keypress/click runs macro text through Blizzard's secure path (secure command options), which is allowed in combat; addon Lua deciding target/spell at runtime is blocked.

- SECURE + COMBAT-SAFE (Blizzard-executed on hardware event, accept secure command options): /cast, /use, /castrandom (see stale note in macro-api clip), /castsequence, /userandom, /stopcasting, /stopspelltarget, /cancelaura, /cancelform, /cancelqueuedspell, /startattack, /stopattack, /petattack plus pet stance commands, /assist, /focus, /clearfocus, /target*, /cleartarget, /targetlast*, /changeactionbar, /swapactionbar, /click (Button:Click; re-entrancy silently ignored), /equip + /equipslot + /equipset (secure path, but game rules still block most gear swaps in combat), /dismount, /leavevehicle, /usetoy, /stopmacro, #show, #showtooltip (display-only, always safe).
- INSECURE / TAINTED (blocked from protected effects, especially in combat): /script, /run, /console (CVar/system side effects; many CVars now RequireNonSecureCVar-guarded), /reload, /logout, /quit, /timetest.
- NOT PROTECTED / combat-irrelevant (work any time, taint-safe, touch no protected state): chat (/say /yell /party /raid /guild /officer /whisper /reply /emote /rw /battleground /csay...), social (/friend /ignore /invite /promote /readycheck /duel /inspect /trade /follow...), UI panels (/macro /achievements /calendar /dungeonfinder /raidinfo /who /played /time /random...), emotes (all /dance /bow etc., cosmetic only), /dump /api /eventtrace /framestack (devtools, insecure read-only).
- DISABLED (parsed, no-op): /usetalents (dual-spec change), /petaggressive (replaced by assist, deprecated 4.2).

## Secure templates (FrameXML/SecureTemplates.xml + SecureTemplates.lua)

Family: SecureActionButtonTemplate (protected actions), SecureUnitButtonTemplate (unit frames), SecureAuraHeaderTemplate, SecureGroupHeaderTemplate (+Party/Raid variants), SecureGroupPetHeaderTemplate (+Party/Raid pet variants). Rules: create + SetAttribute only out of combat (check InCombatLockdown()); inheriting a template keeps secure handlers unless overridden; protection spreads to parents/anchors (re-anchor out of combat releases it); protected status is permanent. SecureHandlers (Patch 3.0+ capability): State, Attribute, Click, DoubleClick (+Drag/MouseUpDown/MouseWheel/EnterLeave/ShowHide stubs); snippets run in RestrictedEnvironment; pre-4.0.1 "control" handle is now an alias of "owner".

## Patch history: protected-function changes 2.0.1 to present (as inspected)

- 2.0 (2006-12, TBC prepatch; Tyren/slouken posts 2006-10-06): secure-execution model introduced. A distinct 2.0.1 delta was not documented on inspected pages.
- 2.3.2: /cast toggles toggleables; "!" prefix prevents toggle-off.
- 3.0: SecureHandlers capability added. 4.0.1: "control" handle becomes owner alias. 4.2: petaggressive to assist.
- 5.2: togglemenu type added. 7.2.0: InsecureActionButtonTemplate added.
- 9.1.5 (2021-11-02): several APIs protected from direct /script calls.
- 11.0.2 (2024-08-13): real macros/macrotext may not /click buttons executing another macro (anti-chain rule).
- 11.2.x-12.1.5 (current Retail): SECRET VALUES model (Patch 12.0.0): combat/PvP/encounter/dungeon-raid APIs return secrets; tainted code may store/pass/concatenate secrets but NOT do arithmetic, compare/boolean-test (except nil/non-boolean truthiness), # length, secret keys, indexing, or calling; violations are immediate Lua errors; testers issecretvalue/canaccessvalue/issecrettable/canaccesstable; SecretReturns/SecretArguments/SecretWhen*/Requires* markup in Blizzard_APIDocumentation; secret predicates (SecretInCombat, SecretOnRestrictedMaps, SecretWhenAurasRestricted 12.1.0, cooldown/aura/unit-identity/threat maps...); preconditions incl. RestrictedForMacroChatMessages (12.0.1: macro-initiated chat restricted in encounters); secret aspects on widgets (Text/Shown/Scale/Alpha/BarValue/...); forbidden tables error on index.
